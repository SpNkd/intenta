# ИНТЕНТА — продуктовая спецификация MVP

Статус: source of truth продуктовой логики. Если реализация или другой документ
противоречат этому файлу, сначала уточняется и изменяется этот файл.

## 1. Суть продукта

**ИНТЕНТА** — mobile-first веб-приложение и личный эксперимент с намерением.

Слоган: **«Намерение — начало того, чего ещё нет.»**

Приложение предлагает пользователю конкретную сумму. Оно не переводит деньги.
Пользователь заранее решает, на что потратит эту сумму для себя, если она
неожиданно появится, сохраняет формулировку и переписывает её от руки. Затем он
живет как обычно, наблюдает и позднее фиксирует произошедшее либо отсутствие
результата.

Основная последовательность:

```text
сформулировал → зафиксировал → отпустил → наблюдал → записал результат
```

## 2. Позиционирование и тон

Интента предоставляет пространство для личного эксперимента и не интерпретирует
опыт за пользователя.

Продукт никогда:

- не обещает появления денег;
- не выдаёт материализацию мыслей за научный факт;
- не утверждает мистическую причинно-следственную связь;
- не объясняет отсутствие результата недостаточной верой или желанием;
- не ставит псевдопсихологические диагнозы;
- не использует лексику про «денежные блоки», «вибрации» и подобное.

Тон спокойный, ясный, тёплый и нейтральный. Формулировки короткие, без давления,
геймификации и категоричных выводов.

## 3. Границы MVP

### Обязательно

- анонимный аккаунт без персональных данных;
- recovery code для доступа с другого устройства;
- безопасные серверные сессии;
- onboarding из 3–4 коротких экранов;
- последовательность сумм 500, 1 000, 2 000, 5 000 и 10 000 ₽;
- создание, физическая фиксация и активация Интенты;
- заранее подготовленная нейтральная техника как часть эксперимента;
- одна незавершённая Интента пользователя;
- фиксация события, отсутствия события или неопределённого результата;
- история Интент;
- mobile-first интерфейс;
- статический, параметризованный контент вне UI-компонентов;
- REST API и PostgreSQL.

### Не входит в MVP

- runtime LLM, OpenAI API или другой генеративный AI;
- email, телефон, SMS, Telegram и социальная авторизация;
- push-уведомления;
- платежи и подписки;
- социальная сеть, профили, sharing;
- достижения, streak, leaderboards;
- админ-панель и сложная аналитика;
- рекомендации;
- микросервисы, Kubernetes, Kafka, Redis и background queues.

Новая функция не добавляется лишь потому, что она типична для других продуктов.

## 4. Термины

- **Анонимный пользователь** — аккаунт без email, телефона, имени и пароля.
- **Recovery code** — единственный пользовательский credential для восстановления
  доступа на другом устройстве.
- **Шаг эксперимента** — конфигурация позиции, суммы, валюты и момента мягкой
  рефлексии.
- **Интента** — зафиксированное пользователем намерение в рамках одного шага.
- **Исходный текст** (`intention_text_raw`) — текст пользователя после удаления
  внешних пробелов, без переписывания смысла.
- **Statement** (`intention_statement`) — детерминированный текст, показанный для
  переписывания на бумагу и сохранённый как снимок.
- **Техника** (`Technique`) — заранее подготовленная нейтральная инструкция,
  сопровождающая эксперимент. Её выбранная версия сохраняется снимком в Интенте.
- **Outcome** — один итог эксперимента: событие, отсутствие события или
  неопределённость.

В пользовательском интерфейсе использовать «Интента» как название объекта и
«намерение» как обычное слово в пояснениях.

## 5. Первый пользовательский путь

### 5.1 Landing

Показывает только необходимое:

- **ИНТЕНТА**;
- **Намерение — начало того, чего ещё нет.**;
- основная CTA **Попробовать**;
- дополнительная CTA **У меня уже есть код**.

### 5.2 Прозрачное создание аккаунта

По нажатию **Попробовать** backend создаёт анонимного пользователя и серверную
сессию. Это не прерывает flow отдельным экраном credential: пользователь сразу
переходит в onboarding. Recovery credential на этом этапе ещё не выпускается, а
значит plaintext secret не нужно временно хранить ни в браузере, ни в базе.

### 5.3 Onboarding

Не более четырёх экранов:

1. Интента предложит тебе сумму для небольшого эксперимента.
2. Заранее решишь, на что потратишь её именно для себя, если она неожиданно
   появится.
3. Запишешь своё намерение от руки.
4. А потом просто посмотришь, что произойдёт.

CTA последнего экрана: **Начать**.

### 5.4 Первая Интента

Первый активный шаг предлагает **500 ₽** и спрашивает:

> Если эти деньги неожиданно появятся в твоей жизни — на что именно ты потратишь
> их для себя?

Поле обязательно; значение обрезается по краям, не может состоять из пробелов и
имеет разумные минимальную и максимальную длины. Copy объясняет, что выбор должен
быть для самого пользователя, но MVP не пытается классифицировать ответ.

После отправки backend создаёт `draft`, сохраняя исходный текст. До активации
пользователь может вернуться и изменить draft.

### 5.5 Физическая фиксация

Экран **Теперь запиши это** просит взять обычный лист бумаги и ручку и показывает
детерминированный statement:

```text
Если в моей жизни неожиданно появятся 500 ₽,
я потрачу их на то, что выбрал для себя:

«Куплю себе хорошие наушники.»

Это моё намерение.
```

Пользователь переписывает его от руки. Фото и проверка почерка не нужны: продукт
доверяет пользователю.

После записи показать короткую заранее подготовленную Технику. Для первого MVP
базовая техника закрепляет сам акт физической записи: спокойно прочитать написанное,
заметить сформулированный выбор и отложить лист. Текст не обещает результата и не
утверждает, что действие вызывает появление денег.

### 5.6 Активация

Подтверждение выполнения инструкции атомарно переводит `draft → active` и записывает
`activated_at`. После активации исходный текст, statement, сумма, валюта,
момент рефлексии, шаг и снимок выбранной Техники неизменяемы. Повторная активация не
создаёт новое состояние.

Подтверждение показывает **Интента создана**, сумму, исходное намерение и текст:

> Теперь ничего специально делать не нужно. Не ищи эти деньги и не пытайся
> подстроить результат. Просто живи как обычно. Если произойдёт что-то неожиданное
> — возвращайся.

После активации приложение переходит к одноразовой выдаче recovery code.

### 5.7 Recovery code после получения первой ценности

Только после активации показать:

- **Сохрани доступ к своей Интенте**;
- recovery code крупно;
- **Скопировать**;
- **Я сохранил код**;
- спокойное действие **Сделать позже**.

Пользователь уже создал Интенту, поэтому экран не является препятствием к первой
ценности. Сохранение настойчиво рекомендуется, но не блокирует переход на home.
Backend возвращает plaintext конкретного credential ровно один раз и не хранит его.
Если выдача не была показана из-за сетевого сбоя либо пользователь потерял код при
живой сессии, можно выпустить замену: старый credential отзывается, новый также
показывается один раз. Без действующей сессии или сохранённого кода доступ
невосстановим.

### 5.8 Главный экран

Главный объект — текущая Интента: сумма, исходный текст, номер дня и спокойный
статус **Наблюдаем**.

- основная CTA: **Кажется, случилось**;
- спокойное, визуально второстепенное действие: **Завершить наблюдение**.

Действия «Пока ничего» как одной из главных CTA нет. Приложение не требует check-in
и не создаёт streak. После `reflection_after_days` на home может появиться мягкий
reflection prompt с вариантами ответить сейчас или продолжить наблюдение. Ни prompt,
ни его игнорирование не меняют серверный статус автоматически. Выбор продолжить
наблюдение может только отложить следующий prompt; active lifecycle не меняется.

## 6. Жизненный цикл Интенты

Канонические состояния:

```text
draft → active → completed
   └────────────→ cancelled (зарезервировано; UI MVP может не предоставлять)
```

Тип завершения хранится в Outcome, а не кодируется вторым набором состояний
Интенты. Это устраняет расхождение между `success/partial/not_happened` и данными
самого результата.

Правила:

- у пользователя одновременно не более одной Интенты в `draft` или `active`;
- draft можно менять, active и completed — нельзя;
- активировать можно только собственный draft;
- один эксперимент имеет не более одного финального Outcome;
- завершение и создание Outcome происходят в одной транзакции;
- исторические значения шага хранятся снимком в Интенте;
- активная Интента не имеет автоматического expiration и остаётся active, пока
  пользователь сам не завершит наблюдение;
- все критические правила проверяет backend, независимо от UI.

## 7. Outcome и завершение

### 7.1 Если кажется, что событие произошло

Flow спрашивает:

1. Что произошло: неожиданно появились деньги; появилась другая сумма; появилась
   возможность получить деньги; произошло что-то похожее; другое.
2. Какая сумма появилась — необязательное неотрицательное денежное значение, если
   у события нет точной суммы.
3. Откуда пришло событие (`source_type`, необязательно): подарок; возврат; бонус или
   кешбэк; дополнительный доход; найденные деньги; экономия или скидка; другое.
4. **Ты знал до создания этой Интенты, что эти деньги должны прийти?** — да / нет /
   не уверен. Ответ сохраняется как `was_expected`.
5. Потратил ли на записанное: да / ещё нет / выбрал другое / не стал тратить.
6. Необязательная заметка.

Продукт не выводит автоматически «успех» из источника, суммы или `was_expected` и
не решает за пользователя, как интерпретировать событие.

Результат показывается рядом с исходной записью, датой и количеством прошедших
дней. Нейтральное завершение: **«Сохраним это как результат твоего эксперимента.»**

### 7.2 Рефлексия и завершение наблюдения

`reflection_after_days` первого шага — 7 дней. Это не deadline и не expiration.
После этого момента приложение может мягко спросить, произошло ли что-то, что
пользователь связывает с Интентой: да / нет / не уверен. Пользователь может ответить,
отложить вопрос или продолжить наблюдение без ограничения срока.

**Завершить наблюдение** доступно как спокойное второстепенное действие. Только
явное подтверждение создаёт финальный Outcome и переводит Интенту в `completed`.
Для ответа «нет» текст остаётся нейтральным: **Это тоже результат эксперимента.**

Backend вычисляет наступление reflection prompt и прошедшие дни по `activated_at`,
снимку `reflection_after_days` и UTC. Prompt сам по себе не меняет состояние;
компоненты не реализуют собственную доменную арифметику дат.

## 8. Следующий эксперимент и история

Начальная лестница шагов: 500, 1 000, 2 000, 5 000, 10 000 ₽. Для начала каждый шаг
имеет `reflection_after_days = 7`, но ни один не имеет автоматического срока.
Вся лестница пользователю не показывается. Следующий шаг определяет backend после
завершения предыдущего. Когда шаги закончились, UI спокойно сообщает об этом и не
создаёт произвольную сумму.

История показывает все Интенты пользователя с суммой, состоянием результата и
фактически прошедшим временем. Детали содержат сумму, исходный текст, statement,
снимок Техники, даты, прошедшие дни, Outcome и заметку.

## 9. Навигация и дизайн

Bottom navigation содержит **Интента** и **История**. Recovery и настройки доступны
из небольшой кнопки в header.

Дизайн сначала проверяется на ширине 320–430 px. Desktop — адаптация. Требования:

- много whitespace и крупная типографика;
- сумма как главный визуальный акцент;
- мало элементов на экране и удобные touch targets;
- спокойный, современный, немного загадочный, тёплый характер;
- premium без пафоса;
- semantic HTML, labels, клавиатурная навигация, видимый focus, достаточный
  contrast и `prefers-reduced-motion`.

Запрещённые визуальные мотивы: чакры, таро, мандалы, астрология, порталы, золотые
монеты, пачки или падающие с неба деньги, эзотерические руки и неоновая
manifestation-эстетика.

## 10. Контент

Продуктовый текст хранится в `content/ru/*.json`, а не распределяется по
React-компонентам. Разрешены статические строки, параметры и выбор из заранее
подготовленных вариантов. Runtime LLM отсутствует.

Важный statement формирует backend, сохраняет в Интенте вместе с версией шаблона и
никогда не пересобирает после активации. Случайный текст, который должен быть
стабильным, сохраняет выбранный ключ/вариант или использует устойчивый seed.

Статический набор Техник хранится в content layer с ключом и версией. Configuration
определяет допустимые техники для шага, server-side selector выбирает одну из них,
а выбранные title/instruction сохраняются в Интенте. Обновление content не меняет
уже созданную историю.

Начальный нейтральный каталог MVP:

- `handwritten_pause`, v1 — **Остановись на минуту**: «Прочитай написанное один
  раз. Заметь, что выбор уже сформулирован. Затем отложи лист и возвращайся к
  обычным делам.» Это базовая техника первого шага.
- `personal_detail`, v1 — **Одна деталь**: «Назови про себя одну конкретную деталь,
  почему ты выбрал это именно для себя. Ничего исправлять или дописывать не нужно.»
- `observation_mode`, v1 — **Наблюдение без поиска**: «Убери лист туда, где он
  останется. Не нужно специально искать подтверждения. Вернись, если захочешь
  записать то, что произошло.»

Техника — часть дизайна эксперимента, а не обещание механизма результата.

## 11. Privacy и события

Не собирать email, телефон, ФИО, возраст, адрес, контакты и социальные профили.
Исходный текст, statement и Outcome — приватный пользовательский контент. API
всегда проверяет ownership объекта.

Допустимый внутренний интерфейс событий/структурированного логирования:

```text
anonymous_user_created
recovery_credential_issued
recovery_code_saved
onboarding_completed
intention_created
intention_activated
outcome_started
outcome_completed
intention_closed_without_result
```

Сторонняя аналитика и полноценная event-driven архитектура в MVP не нужны.

## 12. Критерии готовности первого milestone

- web и API запускаются локально;
- PostgreSQL schema создаётся Alembic migrations;
- anonymous account, recovery code и cookie-сессия работают;
- anonymous session создаётся прозрачно, без credential gate перед onboarding;
- пользователь проходит onboarding и создаёт первую Интенту на 500 ₽;
- draft сохраняется, paper-writing экран показывает сохранённый statement;
- пользователь получает базовую Технику, активирует Интенту, после чего snapshots
  неизменяемы;
- recovery code однократно выдаётся после активации, его можно отложить или заменить
  при живой session без хранения plaintext;
- после logout recovery login возвращает ту же активную Интенту;
- критические backend tests и оба E2E flow проходят;
- mobile layout проверен;
- README содержит актуальные команды.
